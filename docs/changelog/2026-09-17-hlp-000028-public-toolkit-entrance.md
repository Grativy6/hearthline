## What changed

The repository entrance now leads to the
[general public toolkit](../PUBLIC_TOOLKIT.md), with the shared foundation
and broader mechanism catalogue described separately from optional lore.
The [Moltbook index](../LEGACY_MOLTBOOK.md) identifies the old profile as a
subordinate legacy route. The previous README is preserved at
[its historical entry](../../README-MOLTBOOK-0.4-DRAFT.md).

The [build preparation note](../BUILD_PREPARATION.md) records the four
deliverables, independent foundation dependency, reusable existing code,
first contracts, offline verification cases and deferred live-book choices.
The public-content boundary permits implementation source and fabricated
fixtures while continuing to exclude private runtime material. The TETHER
check now checks the new README routes while retaining checks on the original
legacy instruction and manifest.

## Why

Christopher selected a minimal seedPEA foundation and a public Hearthline
entrance that offers that same foundation plus the full supported toolkit.
Users can develop their own version without loading his lore or adopting a
Moltbook-agent identity. The legacy specialization remains available with its
provenance and limits intact.

## Preserved boundaries

PAL, CHARTER, PECAN, PEA and SEED retain distinct source roles and their
authority ceilings. PEACHES stamps remain non-authoritative registration
records. Source availability, review, grant, execution and book inclusion are
separate. FBT and cache-to-cache remain optional research routes with no
general performance claim from this documentation change.

The original agent instructions and candidate manifest are unchanged. The
Moltbook profile is not activated, and its old grants are not renewed.
Personal and family extensions remain separate from public default context.
No new checker, key, Genesis, stamp, MCP runtime or external action is created.

## Compatibility and migration

Existing links to the root legacy agent and candidate manifest remain valid.
The new public profile has its own route and is not a relabeling of that
legacy manifest. Historical instructions retain their original identifiers,
versions and normalized-text hash binding. Earlier history records and the
namespace reservations remain unchanged.

The public SeedPEA preview is a useful existing implementation input; its
declared PAL 2.2 profile requires an explicit mapping before any PAL 2.3
compatibility claim. The public toolkit must not depend on private checkout
access or import the full toolkit into the minimal foundation.
