## What changed

The public entrance leads to MCP installation, technical contracts, tools,
tests, sources and the published [CPX v1.0 preprint](https://doi.org/10.5281/zenodo.23306102).
After verified private preservation, 74 character, artwork, lore and legacy
persona paths are retired from the current tree. Nine mixed documents have
technical editions at their existing paths, with their complete predecessors
linked by commit. The [design index](../DESIGN_CONTRACTS.md) explains their
functions without requiring personal context.

The [history guide](../HISTORY.md) and [public split manifest](../history/public-lab-split.json)
retain exact public source identities. The old candidate/agent and portrayal
checks inspect pinned historical objects. Current technical links must still
resolve in the current tree. `requirements.txt` now agrees with the package
and server's existing `seedpea-foundation==0.2.0` requirement; implementation
code and dependency revisions are unchanged.

## Why

Chris requested a professional public lab whose default does not install his
personal version of Hearthline. The private Cabin had already received the
83 affected originals, so this pass verified and reused that preservation
without repeating the import or publishing any new private material.

## Preserved boundaries

All 23 CPX companion files and all 27 earlier full change records remain
byte-identical. Existing HLP IDs, off-main reservations and branch archives
retain their status. Previously public material remains in Git history. No
history rewrite or confidentiality guarantee is implied. Toolkit operations,
optional personal context and prospective design contracts stay distinct.

## Compatibility and migration

The public package and default MCP need no Cabin checkout or private
credentials. Its founding orientation and optional template behavior remain
unchanged. Users select their own model, operator and context. Legacy root
file consumers must use the explicit pinned links in the
[Moltbook history index](../LEGACY_MOLTBOOK.md). Structural checks need the
pinned public Git objects as documented in [verification](../VERIFYING.md).
No installed runtime, real user state or model is updated by this change.

consistency and whitespace checks passed. A non-failing Pydantic forward-
reference warning remains in the local test log. GitHub matrix results are
recorded separately on the pull request and commit.
